# HOLD — public distribution checklist

Until every mandatory item is satisfied, public distribution of any Android/iOS build or prototype is **not authorized** by the project instructions.

- [ ] Responsible individual/organization legally controls publishing account/domain and has approved branding.
- [ ] Clearly marked independently developed educational product if not institution-backed; no public authority misrepresentation.
- [ ] Khmer/English scenario content independently reviewed for safety and accuracy; recovery advice verified against current official source.
- [ ] No actual OTP, real victim data, third-party logos used without permission, malicious URLs, or unlicensed images/audio/video.
- [ ] Privacy notice, contact for corrections, consent and retention for analytics established.
- [ ] RLS, admin auth/roles, API, upload, secrets and abuse tests passed; independent security review scheduled/completed proportionate to launch scope.
- [ ] Regional legal/copyright/data processing review completed with appropriate local expertise.
- [ ] Supabase backups/storage and at least one restoration drill documented (after services introduced).
- [ ] Media and official contacts validated with evidence and last-checked timestamps.
- [ ] Android signing/build/distribution method approved. iOS build/signed/testing only with appropriate Apple environment/account.
- [ ] Monitoring, emergency withdrawal/retraction, budget caps, and maintenance owners assigned.
- [ ] Owner explicitly approves the **exact build/version and distribution channel**.

A public URL from a prior *web-first* pilot conversation does not authorize a public Flutter build or Play Store release.
